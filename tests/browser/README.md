# Browser walk-throughs

Three Node scripts drive the owner's interface in a real browser, against the real `wdva gate app`.

- `journey_demo.js` walks the demo: its guide on Home (a passage that is not released and does not come back by itself, the played app asking again only when a button tells it to, the passage released and read), then, two presses away under "Settings", on the six pages with every setting the passphrase asked for again, lock and unlock.
- `journey_real.js` walks a new vault through the six pages with every setting, from pairing to Ctrl-C: the two steps of the first run skipped, "Open on" under Settings, then documents, apps, grants, an agent's calls, approvals, the passphrase asked for again, lock and unlock, a restart, and the addresses of an earlier version, which must lead to where their pages are now. On its way it chooses Polish on the pairing screen, on the passphrase screen, for an approval card and on the locked screen: everything that can be read there must then be a text of the page's Polish table (which it reads from the app as the page does) or a name, and a reload keeps the language once the vault exists.
- `journey_basic.js` walks the first run as the page offers it, Home, and the plain pages Documents, Activity, Settings and "How it works and what it cannot do", in five runs with a new vault each: the app, a document, the first question with the look at the settings file, the first request and the first approval; Home empty, on an ordinary day, with a passage waiting, with five waiting, locked, and for a vault that was set up on the six pages; "Open on" under Settings across restarts; a reload, a lock and a restart in the middle of the first run; the app stopped. One step walks every simple page in a window 400 px wide: none may scroll sideways, and the bar with the four entries must stay at the bottom of the window. The same step chooses Polish: on Documents, Activity, Settings and "How it works" everything that can be read must be a text of the Polish table or a name (a command, a path and a moment are data and are left out), and a Word file and a text file that is not UTF-8 are refused in Polish.

To run them, from the top of the repository:

    python -m pip install -e ".[gate]"
    npm install --no-save playwright@1.63.0 && npx playwright install chromium
    node tests/browser/journey_demo.js && node tests/browser/journey_real.js && node tests/browser/journey_basic.js

All three start the app through `launch_app.py`, which changes how long owner mode lasts and gives the app an empty home of its own (`HOME`, `XDG_CONFIG_HOME`), so that "Check the file" never reads the settings of a program on this computer. Where `journey_basic.js` has the page look at the settings file of an AI app, the file is one the script put into that home.

Each step prints `ok` or `FAIL`; the exit status is 1 when a step failed, the page logged an error, a request failed, or an HTTP error came that no step announced. The head of each script lists its options (`GATE_PYTHON`, `GATE_BROWSER`, `GATE_SHOTS`, `GATE_SCALE`, `GATE_PORT`, `GATE_OWNER_SECONDS`; for `journey_basic.js` also `GATE_RUNS`, which walks only the runs it names, for example `GATE_RUNS=A,D`). Screenshots go to `shots/` in this directory: `demo-…` from the demo, `01-…` to `25-…` from the walk through Pro, `b01-…` to `b16-…` from the first run, Home and the plain pages. A step that failed leaves a picture named `…FAILED-step-NN`.

`journey_basic.js` also counts what the offered first run costs a person, from "Create my vault" to the first request of their own AI app seen on the page: presses, the addresses the page was at, fields typed into, file dialogs. It prints the count and fails above its limits: 8 presses, 3 addresses, no typed field and 1 file dialog for Claude Desktop; 6 presses for Claude Code. For Claude Desktop the design counts 7, with one line for a terminal that opens the settings file and holds the text; that line is on the page only after it has been tried against the real applications, and until then the place of the file and the text are two things to copy. Each of its five runs ends by looking at what the page did in the browser: it asked no address but the app's, and it keeps nothing there but its session.

The scripts keep to what Chromium, WebKit and Firefox all do: no launch options, a wait is a wait for a condition, the app's state is read over its own API, and what a "Copy" button copied is read back from the clipboard only in Chromium, the one engine that lets a test do that; everywhere the text is compared with what the page shows beside the button.

On a development machine the three take about one, two and four minutes in Chromium. CI runs all three on every push (job "Browser" in `.github/workflows/tests.yml`): on Linux in Chromium, and on macOS in WebKit, the engine of Safari.
