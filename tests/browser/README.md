# Browser walk-throughs

Three Node scripts drive the owner's interface in a real browser, against the real `wdva gate app`.

- `journey_demo.js` walks the demo: its card on Home (a passage that is not released and does not come back by itself, the played app asking again only when a button tells it to, the passage released and read), the box on Home that asks the documents (it asks for the passphrase once its time is over, shows one passage, and its two buttons send nothing), a tile, which in a demo connects nothing and looks at no file, then, two presses away under "Settings", on the six pages with every setting the passphrase asked for again, lock and unlock.
- `journey_real.js` walks a new vault through the six pages with every setting, from pairing to Ctrl-C. The app is started with `--view pro`, so "Create my vault" opens Overview and no step comes between: documents, apps, grants, an agent's calls, approvals, the passphrase asked for again, lock and unlock, a restart, and the addresses of earlier versions (those of the six pages, of the page that was called Basic and of the three steps of the first run that are gone), which must lead to where their pages are now. On its way it chooses Polish on the pairing screen, on the passphrase screen, for an approval card and on the locked screen: everything that can be read there must then be a text of the page's Polish table (which it reads from the app as the page does) or a name, and a reload keeps the language once the vault exists.
- `journey_home.js` walks Home, the sheets of its four tiles, the box that asks and the plain pages, in five runs with a new vault each. **A**: the offered path with a file of the owner's, for Claude, from the first screen: the three cards of a new vault, a file refused and one sealed, a question in the box (the whole passage is on the card), the tile, the look at the settings file, "Connect", what stands in the file afterwards, a call through that entry, a passage released and read; Documents, Activity (the details of a row open beside the rows and cover none), Settings; Polish; a lock, after which Home still counts the trial questions since the app was started, and the line of the sidebar that says until when the vault is unlocked (one line, without a date for a time within 24 hours); the app stopped. **B**: the write against settings files the script made: no folder, other servers and keys, the two copies, "Disconnect", an entry that points elsewhere, links, broken JSON, a file that changed, owner mode run out. **C**: ChatGPT and Grok (TOML), an entry under another name, a file written in a way the app does not change, `CODEX_HOME` set, and the tile "Other app". **D**: a vault set up on the six pages, with two groups, an app on this computer and a pause: what Home, the box and the sheets say then; "Open on". **E**: the sample document in Polish, a question that finds nothing, five passages waiting, every screen in a window 400 px wide, the app stopped under Home.

To run them, from the top of the repository:

    python -m venv .venv && .venv/bin/python -m pip install -e ".[gate]"
    npm install --no-save playwright@1.63.0 && npx playwright install chromium
    export GATE_PYTHON="$PWD/.venv/bin/python"
    node tests/browser/journey_demo.js && node tests/browser/journey_real.js && node tests/browser/journey_home.js

All three start the app through `launch_app.py`, which changes how long owner mode lasts and gives the app an empty home of its own (`HOME`, `XDG_CONFIG_HOME`; `GROK_HOME` and `CODEX_HOME` of the computer are removed), so that a look at a settings file, and a write into one, never meets the settings of a program on this computer. Every settings file `journey_home.js` has the app look at or write is one in that home.

**Where the vaults and the homes lie.** `journey_home.js` has the app write an entry into a settings file, and the app writes no entry that names a Python or a vault in a place that may be gone or exchanged tomorrow: a folder for temporary files, a folder everybody may write, a folder of another account. So the vaults and homes of a run lie under the checkout, in `tests/browser/.run/<three characters>/` (left out of version control, removed when the run ends; `GATE_RUN_DIR` names another place), and the Python must lie in a place of your own too: a virtual environment under the checkout, as above, will do. Before it starts, the script asks the app's own rule (`launch_app.py --can-connect`). Where the rule refuses, it prints a line that begins with `#####` and says which Python and which folder, and ends with status 1. With `GATE_NO_CONNECT=skip` it walks on without everything that connects: each step it leaves out is printed as `SKIP`, and the runs B and C are not started. A vault's socket path may have 100 bytes: where the checkout lies too deep for that, the run's folder is made in the home folder of the account instead, which is said in a note.

Each step prints `ok` or `FAIL`; the exit status is 1 when a step failed, the page logged an error, a request failed, or an HTTP error came that no step announced. The head of each script lists its options (`GATE_PYTHON`, `GATE_BROWSER`, `GATE_SHOTS`, `GATE_SCALE`, `GATE_PORT`, `GATE_OWNER_SECONDS`; for `journey_home.js` also `GATE_RUNS`, which walks only the runs it names, for example `GATE_RUNS=A,D`). Screenshots go to `shots/` in this directory: `demo-…` from the demo, `01-…` to `25-…` from the walk through the six pages, `h01-…` to `h54-…` from Home. A step that failed leaves a picture named `…FAILED-step-NN`.

`journey_home.js` also counts what the path costs a person **from the first screen of the page** (pairing), in runs A (with a file of the owner's) and E (with the sample document): presses, fields typed into, file dialogs. It prints three figures with every press named, and fails above its limits: 4 presses to the first passage in the box that asks, 6 to "Connected", 7 to the first passage a caller reads through the written entry. The interface is designed to 3, 5 and 6, and the script prints a note when a count is higher. The sheet that says "Connected" is closed with the Escape key before the third figure; closed with its button "Done" that figure is one higher. Not counted, and not the page's to shorten: installing, the command in a terminal, and reading the pairing code there.

"Connected" means in these scripts what the page means by it: the entry was written into the settings file and read back. **No AI app takes part in any walk-through.** A call "through the written entry" is made by `agent_call.py`, started with the Python, the vault and the name that stand in the settings file the app wrote; what Claude Desktop, the ChatGPT desktop app, Codex or Grok Build do with such an entry is not tried here. `read_settings.py` reads the settings files with `json` and `tomllib` of the standard library, so that the app's own reader is not what checks the app's writer.

Each run of `journey_home.js` ends by looking at what it left: the page asked no address but the app's, it keeps nothing in the browser but its session, the app quit with status 0 and an empty standard error, and the run's home holds exactly the files the run expects (the settings files and their copies, no temporary file).

The scripts keep to what Chromium, WebKit and Firefox all do: no launch options, a wait is a wait for a condition, the app's state is read over its own API, and what a "Copy" button copied is read back from the clipboard only in Chromium, the one engine that lets a test do that; everywhere the text is compared with what the page shows beside the button.

On a development machine the three take about two, two and three minutes in Chromium. CI runs all three on every push (job "Browser" in `.github/workflows/tests.yml`): on Linux in Chromium, and on macOS in WebKit, the engine of Safari. There the package is installed into a virtual environment under the checkout, for the reason given above.
